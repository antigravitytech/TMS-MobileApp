# Routine API Documentation

Source: `tms/routines/routers.py`

**Prefix:** `/routine`

Routines are recurring workspace work. They come in two kinds:

| Kind | Purpose |
| --- | --- |
| `report` | Structured recurring reports with configurable fields and logs |
| `task` | Recurring task templates that generate independent tasks |

Recurring tasks created directly through `POST /task/create-task/` use a
`RecurringTaskRule`; both schedule types are generated by the
`routines.tasks.generate_recurring_tasks` Celery beat task.

All endpoints require `Authorization: Bearer <JWT>` and an active workspace
membership. Creating, updating and deleting routines requires an owner/admin.

## Schedule fields

| Field | Values |
| --- | --- |
| `frequency` | `daily`, `weekdays`, `weekly`, `monthly` |
| `weekdays` | Uses the workspace's configured `working_days` |
| `weekday` | Full weekday name (`Monday`…`Sunday`), required for weekly/monthly |
| `due_time` | `HH:MM`, interpreted in the workspace timezone |
| `opens_before_minutes` | `0` = start of day, otherwise minutes before `due_time` |
| `late_policy` | `flag` (allow late, mark it) or `block` |
| `late_days` | Catch-up window when `late_policy=flag` |
| `review_mode` | `manager` or `none` |
| `assignee_scope` | `all`, `team` or `person` |

## Report field types

| Type | UI control |
| --- | --- |
| `long` | Paragraph |
| `short` | Single-line text |
| `number` | Number input |
| `choice` | Select from `options` |
| `rating` | 1–5 rating |

At least one report field must be required. Field payloads also accept an
optional `id`; when updating a routine, send the existing field ids so
historical log answers keep pointing at the same question. Submitted answers
are validated against the field type (`choice` options, numeric `number`,
and 1–5 `rating`).

## Occurrence state

| State | Meaning |
| --- | --- |
| `notyet` | Today, before logging opens |
| `open` | Today, accepting on-time logs |
| `overdue` | Today, late is allowed |
| `closed` | Today, late logging is blocked |
| `done` | Logged on time |
| `late` | Logged late |
| `catchup` | Past occurrence still inside the catch-up window |
| `missed` | Past occurrence outside the catch-up window |
| `upcoming` | Future occurrence |

## GET `/routine/list-routines/{workspace_id}/`

- **Auth:** Active member. Members only see active routines; managers may
  pass `active=true|false`.
- **Query:** `active`, `team_id`, `page`, `page_size`.

  "user_name": null,

## POST `/routine/create-routine/{workspace_id}/`

- **Auth:** Owner/admin.

```json
{
  "title": "Daily Status Update",
  "kind": "report",
  "active": true,
  "assignee_scope": "team",
  "team_id": "33333333-3333-4333-8333-333333333333",
  "frequency": "weekdays",
  "due_time": "17:00",
  "opens_before_minutes": 0,
  "late_policy": "flag",
  "late_days": 1,
  "review_mode": "manager",
  "allow_attachments": true,
  "fields": [
    {
      "label": "What did you finish today?",
      "field_type": "long",
      "required": true
    },
    {
      "label": "Blockers",
      "field_type": "short",
      "required": false
    }
  ]
}
```

For a `task` routine, use `task_priority` and `task_description`; generated
tasks are created for each applicable member on each due date.

Returns the routine shape.

---

## GET `/routine/get-routine/{routine_id}/`

Returns one routine with fields, member count and completion rate.

## PUT `/routine/update-routine/{routine_id}/`

- **Auth:** Owner/admin.
- **Description:** Partial update. Sending `fields` replaces the full field
  list; omit it to keep existing fields.

## DELETE `/routine/delete-routine/{routine_id}/`

Soft-deletes the routine. Returns `{ "message": "Routine deleted successfully." }`.

## POST `/routine/submit-log/{routine_id}/`

- **Auth:** A member the routine applies to.
- **Description:** Submit (or update) a report for one occurrence. Required
  fields are validated against the routine definition.

```json
{
  "occurrence_date": "2026-10-24",
  "answers": {
    "bbbbbbbb-bbbb-4bbb-8bbb-bbbbbbbbbbbb": "Shipped the reports endpoint."
  },
  "files": [
    { "name": "evidence.pdf", "url": "https://example.com/signed" }
  ]
}
```

Returns the routine log with `status: "pending"` when manager review is on,
otherwise `logged`.

- **Auth:** Self, line manager or workspace manager.
- **Query:** `occurrence_date` (required), `user_id` (optional).

## GET `/routine/list-logs/{routine_id}/`

- **Auth:** Self, line manager or workspace manager.
- **Query:** `user_id`, `date_from`, `date_to`, `page`, `page_size`.

## POST `/routine/review-log/{log_id}/`

- **Auth:** The member's line manager or a workspace manager.
- A member cannot review their own report.

```json
{ "note": "Thanks — clear and complete." }
```

Marks the report `reviewed`, records the reviewer/time and notifies the author.

## POST `/routine/upload-attachment/{routine_id}/`

- **Auth:** A member the routine applies to; routine must allow attachments.
- **Content type:** `multipart/form-data` (`file`).
- **Description:** Upload report evidence to B2 and return metadata to include
  in `submit-log.files`:

```json
{
  "name": "evidence.pdf",
  "url": "https://example.com/signed",
  "file_key": "routine-logs/...",
  "file_size": 245760,
  "content_type": "application/pdf",
  "expires_at": "2026-10-31T10:00:00Z"
}
```

Signed routine attachment URLs are renewed by the `renew-file-urls` beat task.

## GET `/routine/export-logs/{routine_id}/`

- **Auth:** Owner/admin.
- **Query:** `limit` (default 7, max 31).
- **Response:** `text/csv` attachment (`routine-logs.csv`) with person, date,
  status, logged time and one column per report field.

## Recurring tasks

`POST /task/create-task/{workspace_id}/` accepts `type: "recurring"` with:

```json
{
  "title": "Daily report",
  "type": "recurring",
  "assignee_ids": ["44444444-4444-4444-8444-444444444444"],
  "repeat_frequency": "weekdays",
  "repeat_weekday": null,
  "repeat_time": "17:00",
  "start_date": "2026-10-24",
  "due_date": "2026-10-24"
}
```

The request creates a `RecurringTaskRule` and today's task(s). The Celery beat
task generates future occurrences idempotently per rule/occurrence date.
Routine-due reminders are sent hourly at the routine's due hour by
`routines.tasks.send_routine_reminders`.
`GET /task/get-task/{task_id}/` exposes `recurring_rule_id` and
`occurrence_date`.

## GET `/routine/list-summaries/{workspace_id}/`

Returns the daily-summary grid used by My Day and Reports.

- **Auth:** Active member. Managers and admins see everyone; other members
  see themselves and their direct reports.
- **Query:** `days` (default 14, max 365), optional `user_id`, optional
  `team_id`.

```json
[
  {
    "id": "11111111-1111-4111-8111-111111111111:2026-11-19",
    "user_id": "11111111-1111-4111-8111-111111111111",
    "date": "2026-11-19",
    "submitted": true,
    "late": false,
    "done": "Shipped the report",
    "blockers": "None",
    "plan": "Start the next one",
    "linked": null,
    "reactions": [
      {
        "emoji": "🔥",
        "count": 2,
        "mine": false,
        "by": []
      }
    ],
    "can_react": true
  }
]
```

Summaries are computed from submitted `report` routine logs. The `done`,
`blockers` and `plan` values are read from fields whose labels contain
`finish`/`done`/`did`, `block`, and `next`/`plan`/`tomorrow` respectively.

## POST `/routine/react-summary/{workspace_id}/{summary_id}/`

```json
{"emoji": "🔥"}
```

Toggles the caller's reaction on a summary. Only a manager/admin or the
person's line manager can react, and nobody can react to their own summary.
The summary author receives a notification when the reaction is added.
Returns `{id, reactions: [{emoji, count, mine}]}`.
